# Light-DMP checklist

*A compact one-page DMP for small, low-risk projects. It covers the minimum set of decisions every CMI project needs to record, without the full institutional template's depth. If your project touches personal data or higher sensitivity tiers, use the [full CMI DMP template](dmp-template-full.md) instead.*

## When to use this checklist

Use this checklist if **all** of the following apply:

- The project is entirely Green or Yellow tier (see [Data classification](data-classification.md)).
- The project does not process personal data, or processes only minimal indirect identifiers that are removed early.
- The project is short in duration and limited in partners (single institution or small stable consortium).
- The funder does not mandate a specific DMP format.

If any of these do not hold, use the [full CMI DMP template](dmp-template-full.md) or the [inventory-centred variant](dmp-template-inventory.md).

## What data

- [ ] **Data types listed.** What data the project collects or acquires (types, formats, approximate volumes).
- [ ] **Sensitivity classified.** Each dataset tagged Green or Yellow per [Data classification](data-classification.md). If any dataset is Red or Black, stop and use the full template.
- [ ] **Secondary data documented.** For reused data, source, access conditions, and licence recorded.

## Where stored

- [ ] **Storage location named.** Primary storage on CMI M365 (default) or an equivalent approved service, with encryption, MFA, and role-based access.
- [ ] **Backups verified.** Backup location and frequency recorded.
- [ ] **File and folder naming agreed.** Conventions documented per [Name files and structure folders](file-and-folder-naming.md).
- [ ] **Documentation standard set.** At minimum, a README per dataset describing contents, collection context, and any limitations.

## Who is responsible

- [ ] **Roles named.** PI plus at least one data steward (may be the PI in a small project).
- [ ] **Handover plan noted.** How data responsibilities transfer if a team member leaves.

## What happens after

- [ ] **Sharing pathway chosen.** Default: open access via Zenodo with CC BY 4.0 or CC0 licence. Note any deviation.
- [ ] **Embargo stated.** CMI default is 1–2 years after project completion; shorter or no embargo preferred where possible.
- [ ] **Retention period set.** CMI defaults: primary research data 10 years, administrative records 5 years. Note the deletion procedure.
- [ ] **Metadata record planned.** A metadata record is deposited even if data cannot be shared.

## Review

- [ ] **Review points scheduled.** At minimum: mid-project and before final outputs.
- [ ] **Living document.** This checklist will be updated with the project's [data inventory](data-inventory.md) at each review.
