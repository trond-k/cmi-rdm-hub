# Data inventory approach for CMI

This folder is a synthesis track. It keeps the best parts of the three existing inventory drafts while changing the emphasis:

- use the accessible language and practical framing from `data-inventory-appraoch-openai`
- keep the strongest concept from `data-inventory-approach`: manage data object by object
- retain the pragmatic workflow from `data-inventory-appraoch-current`
- hide the full schema behind optional reference material

The aim is not to make CMI researchers maintain a complete metadata system. The aim is to give each project a usable working overview of its data: what exists, where it lives, who is responsible, what risks or restrictions apply, and what should happen to it over time.

## Core principle

The inventory should answer practical questions:

1. What data object are we talking about?
2. What does it contain and where did it come from?
3. Who is responsible for it?
4. Does it contain personal, sensitive, restricted, or contextually risky material?
5. Where is the authoritative copy stored?
6. Who may access it?
7. What is its current status?
8. What should happen to it later?

If a field does not help answer a real decision, it belongs in optional guidance, not in the starter inventory.

## Editorial direction

Use ordinary research language first. Prefer labels such as "Storage location" and "Who has access" over code-like field names in front-facing pages.

Use examples to do much of the teaching. CMI projects often differ by method, partner arrangement, country context, participant exposure, and data sensitivity. A short worked example is usually clearer than a long field definition.

Keep the inventory at category level by default. One row can cover "pseudonymised interview transcripts from work package 2" if the same storage, access, sensitivity, responsibility, and retention decisions apply. The inventory is not a file list.

Treat uncertainty as useful information. "Unknown", "to be reviewed", and "not yet decided" are acceptable early entries if they trigger follow-up.
