# Data inventory template

## Purpose

This template provides a reusable structure for inventorying the research data your project collects, generates, and reuses. It is designed to work as a standalone document and as the basis for Section 3 of CMI's institutional DMP template.

Use it at any stage of the project lifecycle:

- **Planning**: draft an initial inventory when writing the proposal or DMP
- **Active research**: update as data collections begin and new sources emerge
- **Mid-project review**: revise at the project mid-point or after significant design changes
- **End of project**: finalise as a definitive record of what was collected and where it ended up

## Scope

The inventory covers **primary research data** (data you collect or generate) and **secondary research data** (existing datasets you reuse or analyse). Administrative records, ethics documentation, and compliance artefacts are managed separately.

## What is a data record?

A data record is a coherent grouping of related files or datasets, organised around a single data collection activity or analytical process. It is not an individual file. For example, 'key informant interviews in Sfax' is one record covering the audio files, transcripts, and coded outputs from that interview series. 'Household baseline survey' is one record covering the instrument, raw responses, and cleaned dataset.

When your project has six or more records of a similar type (e.g., interview series with different participant groups across multiple sites), you do not need a full entry for each. Use the summary table below to describe the set, and provide a full record only for those that differ materially in sensitivity, storage, or sharing pathway.

## Per-record entries

Create one entry per data record (or per group of similar records). Target 15–20 lines per entry. State what will be done, not why; rationale belongs in the DMP's cross-cutting policies section.

### [N]. [Name of data record]

**Description and method:** What this data is and how it is collected or generated. 1–2 sentences.

**Formats and estimated volume:** File formats and approximate size or count. One line.

**Data flow:** Chain from collection to end state. Use the concise chain format:

> *[Collection format] → [processing step] → [intermediate form] → [final/archived form]*

Expand to a short paragraph only if the flow has branches or non-obvious steps.

**Personal data and sensitivity:**

- Categories: [direct identifiers / indirect identifiers / special category data / none]
- Sensitivity tier: [Green / Yellow / Red / Black]
- Key risk: [one sentence]

**Storage and security:**

- Storage: [where stored]
- Access: [who has access]
- Fieldwork measures: [if applicable; omit if not]

**Sharing and archiving:**

- Pathway: [open / registered / controlled / restricted / no external sharing]
- Target repository and licence: [e.g., Zenodo, CC BY 4.0]
- Embargo: [if applicable; omit if not]
- If restricted: [whether a metadata-only record will be deposited]

**Status:** [planned / in collection / complete / archived / deleted]
