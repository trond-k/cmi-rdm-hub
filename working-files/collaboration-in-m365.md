# Collaborate in Microsoft 365

Use this guide when project files are moving through Teams, SharePoint, or OneDrive and you need collaboration that does not quietly turn into access sprawl.

CMI's default collaboration environment is Microsoft 365. That does not mean every sharing option is appropriate for every project.

## Put files in the right place first

The first decision is where the files should live:

- **OneDrive** is for personal work in progress and files you are not yet ready to expose to a team.
- **SharePoint or Teams** is for project material that multiple people need to access, edit, or hand over later.
- In Microsoft Teams, channel files are stored in SharePoint. If people need a shared project library, use that shared space rather than an endlessly re-shared OneDrive folder.

If the same folder keeps being shared with the same people, it probably belongs in SharePoint or Teams.

## Share narrowly

For research material, narrower is usually better:

- prefer team or site membership, or `Specific people` links
- avoid `Anyone with the link` for project data
- remember that folder sharing exposes future contents too
- share a file instead of a whole folder when only one item is needed

If someone only needs to send material in, use Microsoft's [File Request](https://support.microsoft.com/en-us/office/create-a-file-request-f54aa7f8-2589-4421-b351-d415fc3b83af) feature rather than giving them browse access.

## Know the external collaboration options

Microsoft 365 offers different external routes, and they are not interchangeable:

- **Guest access** is for named external collaborators who need real access to a Team, site, or shared files.
- **External access** is mainly for chat, calls, and meetings across organisations. It does not by itself create file access.
- **Shared channels** can work for recurring cross-organisational collaboration, but they require setup and should be arranged with IT rather than improvised.

If external people need continuing access to project data, settle the role and agreement questions first in [Clarify partners, processors, and data roles](partners-and-data-roles.md).

## Use version history instead of duplicate-file chaos

When files sit in OneDrive or SharePoint, Microsoft 365 gives you co-authoring and version history. Use that before inventing parallel file names as a substitute for collaboration control.

That does not remove the need for a clear folder structure or documented transformations. Use [Name files and structure folders](file-and-folder-naming.md) and the [Data transformation log](../templates-and-checklists/data-transformation-log.md) where the work changes data or analysis files materially.

## Review and remove access

Treat access review as normal project maintenance:

- check permissions when people join or leave
- remove stale guest access and old sharing links
- revisit permissions if the data becomes more sensitive than first assumed
- keep high-risk material in smaller, explicitly controlled locations

Use [Choose storage and control access](storage-and-access.md) if the project still lacks a clear access model.

## When to stop and ask for help

Do not improvise if:

- the material includes personal, confidential, or high-risk data
- an external collaborator needs ongoing access
- the project needs download blocking, extra audit controls, or stronger restrictions than the default team setup
- you are not sure whether standard M365 is enough for the most sensitive files

For technical setup, contact [help@cmi.no](mailto:help@cmi.no). For data-management questions, contact [rdm@cmi.no](mailto:rdm@cmi.no).
